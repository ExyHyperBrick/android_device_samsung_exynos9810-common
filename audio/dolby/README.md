# Dolby extraction and provenance

The Dolby settings application and integration are source-built here. Proprietary
libraries, the DMS executable and its tuning are extracted into
`vendor/samsung/exynos9810-common` by the regular `extract-files.py` entry points.
Their module definitions are generated by `setup-makefiles.py`.

## Verified firmware inputs

* Motorola Edge 30 Ultra (`eqs`), `T1SQ33.15-11-137-10` / `71a49`:
  [public firmware dump](https://dumps.tadiphone.dev/dumps/motorola/eqs/-/tree/b57f578404ab23fe583bd52f6cb89d16274dda12).
  The engine, service, interface, parameter libraries and tuning come from
  `vendor`. Both `libstagefright_foundation.so` files come from `system/lib*`.
* ZTE P855A01, `RKQ1.201221.002` / `20211215.223102`:
  [public firmware dump](https://dumps.tadiphone.dev/dumps/zte/p855a01/-/tree/9c88f819e4d9ecd6430fd95cbfffde450728e296).
  `libsqlite.so` comes from `system/apex/com.android.vndk.current/lib64`.
  The ordinary `system/lib64/libsqlite.so` is a different ICU-dependent build.

The dump repositories represent the system image under `system/system`; normal
Android extraction layout uses `system`. Each input and its fixed-up output have
separate SHA-1 pins in `proprietary-files.txt`.

The firmware libraries were compared byte for byte with the inputs used by
[Rei Ryuki's DolbyAtmosSpatialSound v4.2 port](https://github.com/reiryuki/Dolby-Atmos-Spatial-Sound-Moto-Edge-30-Ultra-Magisk-Module/tree/6b3e7b3af0f4fd2ddad1368cec8a079da5dbe408).
The firmware originals reproduce the installed payload after the recorded fixups.
The third-party port is retained as integration provenance, not as the required
source of the proprietary inputs. Its MIT license does not license the Motorola,
Dolby or ZTE binaries.

## Reproducible compatibility changes

`extract-files.py` records the private library names and `motod` data/config paths
as equal-length byte replacements. It leaves the public HIDL interface name and
media MIME types intact. It also disables volume leveling in the tuning, then
applies the port's empty graphic-equalizer presets. That small adapted patch is
credited to Rei Ryuki; its MIT notice is retained in `LICENSE.port`.

The fixed-up hashes match the previously shipped 9810 payload. No engine,
profile, gain or audio-route change is intended by this extraction migration.

## Extraction

From the common device directory, use the standard command:

```sh
./extract-files.py /path/to/extracted-lineage-installation
```

The per-device extraction scripts for starlte, star2lte and crownlte also process
this common list. An installed Lineage image contains the destination paths and
already-fixed bytes, which are accepted through the fixed-up pins without
patching them again. A fresh extraction must have access to these files; a
Samsung stock image alone does not contain the Motorola/ZTE payload.

To reproduce the Dolby payload from the listed public firmware dumps, first
normalize their partition layout, then select the matching section in each dump:

```sh
./extract-files.py --no-cleanup --section 'Audio - Motorola Dolby (Motorola*' /path/to/eqs-dump
./extract-files.py --no-cleanup --section 'Audio - Motorola Dolby SQLite*' /path/to/p855a01-dump
./setup-makefiles.py
```

Pinned files already present in the vendor tree are deliberately preserved by
extract-utils. For a fresh source verification, use a disposable vendor checkout
without the corresponding destination files. Extraction does not download blobs.

The local `configs/service.rc` and `configs/service.xml` are source integration,
installed as dependencies of the generated DMS module. Their existing install
paths remain `vendor/etc/init/service.rc` and
`vendor/etc/vintf/manifest/service.xml`.
